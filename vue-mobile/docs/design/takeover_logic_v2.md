# 游戏接风与轮次流转逻辑设计文档 (v2.0)

## 1. 核心理念
- **统一流转**：所有出牌和不要（Pass）操作均采用统一的逆时针索引递增逻辑 `(i + 1) % playerCount`，并跳过手牌为空的玩家。
- **回环确权**：当计算出的下一个玩家索引等于本轮“最后出牌人”时，判定本轮结束并结算。
- **权力继承**：接风本质上是“新一轮开启权”的继承。如果赢家跑路，由策略选出继承人开启新轮次。

## 2. 详细逻辑规约

### 2.1 轮次结束触发器 (Cycle Detection)
在玩家执行 `Pass` 或 `Play` 动作后计算下一个玩家。
- **条件**：`calculateNextActivePlayer(currentIndex) === round.lastPlayPlayerIndex`
- **动作**：
  1. 结算该轮所有分值（手牌分 + 墩分）。
  2. 封存并结束当前 `RoundData`。
  3. 判定是否开启新轮次或结束游戏。

### 2.2 接风继承权 (Takeover Logic)
由 `Strategy.findNextPlayerForNewRound(winnerIndex)` 决定：

#### 个人模式 (Individual Mode)
- 赢家有牌：返回 **赢家**。
- 赢家没牌：**逆时针**寻找第一个有牌的活人。

#### 团队模式 (Team Mode)
- 赢家有牌：返回 **赢家**。
- 赢家没牌：**仅在同阵营（队友）中**逆时针寻找第一个有牌的活人。
- **终止条件**：如果所有队友都出完牌（找不到继承人），返回 **null**。

### 2.3 游戏终止判定 (Game Termination)
- **触发点 1**：接风继承人返回 `null`（意味着某阵营全员撤离）。
- **触发点 2**：每手牌执行后，裁判扫描是否存在某一阵营手牌全空。
- **结算结果**：根据 `finishOrder` 判断排名（头名归属），判定“关三/关双/关单”。

## 3. 物理方位映射规约
为了消除引擎底层与 UI 层的冲突，系统强制统一以下映射关系：
- **物理索引 (Index)**: `0` (南/自己), `1` (东/右), `2` (北/上), `3` (西/左)
- **流转顺序**: 简单的索引递增 `(i + 1) % 4`。
- **UI 布局**: 保持上述对应的物理位置呈现，确保“逆时针”体觉（下->右->上->左）与逻辑一致。

## 4. UI 同步与感官设计

### 4.1 感官延迟 (Pacing Delay)
为了防止 AI 决策过快（尤其在关闭 TTS 时）导致的人类观察困难和 UI 渲染抖动：
- **保底延迟**：在 `gameStore.ts` 的 `advanceGameFlow` 中，若 TTS 未启用，强制加入 **600ms** 的最小操作间隔。
- **状态缓冲**：语音报牌（如果启用）会在“开始播放”而非“结束播放”时触发下一步，平衡反馈速度与体感。

### 4.2 标签自动清理
- **监听清理**：UI 层通过监听 `rounds.length` 的变化，在开启新一轮时自动 `passStatus.clear()`。
- **动作反馈**：当任何玩家成功执行 `Play` 动作时，立即清理所有现存的“不要”标签。
